For engineers and researchers

Reproduce it, verify it, fork it

This page is the short version. The full guide is docs/ENGINEERING.md in the repository.

AI models wrote all of the code, and no person has checked the code or the results yet. Read it as you would read any unreviewed code. The project is built so that you can check it.

How a number reaches this site

  1. Downloaded data stays outside the repository, in the folder that OBL_DATA names. Exam questions and passages never enter git.
  2. An experiment script in open_book_law/experiments/ runs one configuration and writes one run file.
  3. Run files in results/runs/ hold the code commit, data hashes, the model version, the full settings and one row per question. They hold IDs and scores, and no question text.
  4. Summary scripts read only run files. They apply the rules of the plan and write results/summary/, docs/RESULTS.md and docs/REPRODUCTION.md.
  5. tools/build_site_data.py reads the summaries and run files and writes site/data.js. This site shows only that data.
  6. CI repeats steps 4 and 5 on every push and fails if any file changes.

Three levels of reproduction

Level 1 · minutes · Python 3.11 or newer and NumPy

Rebuild every result from the run files

This needs no exam data, no model and no graphics card.

git clone https://github.com/Akari-H-111/open-book-law.git
cd open-book-law
python3 -m venv .venv
.venv/bin/pip install numpy
ok=yes
for m in us_answers us_verdicts us_select us_hypotheses; do
  .venv/bin/python -m open_book_law.experiments.$m || ok=no
done
.venv/bin/python -I tools/build_site_data.py || ok=no
test -z "$(git status --porcelain)" || ok=no
echo "Same results: $ok"

The last line prints Same results: yes only if every script ran and no tracked file changed. Then you rebuilt the summaries of the tests, the tables in both results documents and the data of this site, byte for byte. The scripts do not rerun the experiments: they start from the stored run files.

Level 2 · minutes

Rebuild the release files and compare checksums

git checkout v1.0.0
.venv/bin/python -I tools/make_release.py v1.0.0 --verify && cat dist/SHA256SUMS

The script reads every file from git's stored objects for that commit. It writes the zip files with fixed metadata, so the checksums must equal the SHA256SUMS file on the release page.

Level 3 · days · an Apple Silicon Mac and the datasets

Run the experiments again

The readers run through MLX, so this level needs a Mac with Apple Silicon. You also need the public datasets, several gigabytes of disk space and days of computing. The engineering guide lists the files, the pinned model versions and the commands. Each run file records the SHA-256 hash of every data file that it read, so you can check that you have the same data.

Verify a download

shasum -a 256 -c SHA256SUMS

Run this in the folder that holds the downloaded files. Each line must end in OK. Each zip file also holds a MANIFEST.sha256 with a checksum for every file inside it.

Fork and extend

  • A new reader model. Add it to READERS in open_book_law/reader/mlx_reader.py, and pin its revision in data/model_revisions.json.
  • A new library. Add a set of passage sources to LIBRARIES in open_book_law/us/barexam.py.
  • A new test. Write the claim, the measure and the threshold into the plan first, as a dated amendment. Then add the test to open_book_law/experiments/us_hypotheses.py.
  • Keep the rules. Run files are never edited: a rerun writes a new file. No question text or passage text goes into git. Every number in a document must come from a script.

The guide explains each of these with the files to touch and the tests to run. The license is MIT.

Known limits of the code

  • No person has reviewed the code. Other AI models reviewed parts of it, and the fixes are in the record.
  • The readers need MLX, so the experiments run only on Apple Silicon.
  • Three run files have a run ID that no longer equals the hash of their stored settings. docs/PATHS.md explains why.
  • The public repository starts from a single commit. The earlier history is private.
